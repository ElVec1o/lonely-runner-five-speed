# drivers (documentation of the development build order; NOT part of the supported route)

These shell scripts are copies of the drivers that built the five-speed tree incrementally during development. They are shipped as documentation only and are not runnable as shipped: the path prefix `/DEV_TREE` stands for the root of the development tree (the original absolute prefix was replaced when the repository was prepared), they take lane locks, read a guard log of other jobs on that machine, and write progress state next to themselves. They are shipped so that the order and the per-module protocol are inspectable; the supported route is `repro/build.sh` and `repro/regen_data.sh`.

* `lean5_data/emit_all.sh`: batches of 50 representatives through the v3 emitter `l5v3` (`V3=1`, `TAG=r`; the parameters `PR=300 LAYOUT=A` that reproduce `inputs/MANIFEST_v3r.sha256` were found by search, see `repro/README.md`).
* `l5_rollout/rep_run.sh REP`: the per-representative pipeline: copy the node-side modules (`GD3N<rep>`, `...M<k>`, `...Z`, `GD3F2N<rep>`) into the Lean tree, run `l5s4o` (class tables, chunk modules, main module), build the import closure bottom-up one module at a time (`build_mod.sh`: lane lock, memory/disk gate, own 9 GB tree killer, retries after guard kills), check the axioms of `N<rep>.t3_nodeU` (`axcheck.sh`), delete the blobs. `rollout.sh` loops over `rollout_order.txt` (cost ascending); results in `rollout_results.tsv`.
* `l5_lines_driver/`: the lines stage: `emit_all.sh` (batches of 50 plan lines through `l5qemit emitc`), `mkorder.sh` (build order: `LinRCov`, chunks by ascending cost, then group and node assemblies, `LinRAll`, `LinRFinal`), `driver.sh`.
* `../l5_reg/*.sh` (registration `Reg<rep>`, `RegFin<g>`), `../l5_agg/*.sh` (aggregation: `gen`, `pending`, `build_all.sh`, `loop.sh`), `../l5_hlines/*.sh` (mirror, levels L M D T): same remark.
